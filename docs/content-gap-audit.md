# Content Gap Audit — PRD vs. codebase

Source: *RIL AI-Powered Digital Marketing & Growth Platform — Comprehensive PRD* (Sept 2026), `pdf.txt`.
Audited: 2026-10-02, against the code in this repository. No code was changed.

## Scope

Only the content parts of the PRD:

- §6.3–6.8: repurposing engine, video → blog, newsletter and short-form, image captioning, social content generator
- §6.9: social publishing
- §6.10–6.11: content calendar and AI calendar generator
- §6.12: industry trend → content
- §6.16: registration links, as they attach to content assets
- §6.20: SEO, as applied to blog drafts
- §6.24: content library
- §6.25 / §11: approval workflow
- The content entities in §7, the content parts of §8, and the content edge cases in §13

Out of scope: leads/CRM, email delivery, landing pages, ads, analytics, community, and the brand knowledge base. They come up below only where content depends on them.

## Legend

| Status | Meaning |
|---|---|
| **Done** | Works end to end from the UI through to the database or integration. Any follow-ups are small. |
| **Partial** | Some of it exists (UI, action, or table), but logic, data, wiring or integration is missing, stubbed, or hard-coded. |
| **Missing** | No meaningful implementation. |

| Effort | Meaning |
|---|---|
| **S** | ≤ 1 day |
| **M** | 2–5 days |
| **L** | 1–3 weeks |

## Summary

**35 requirements: 3 Done · 22 Partial · 10 Missing.**

The pipeline from activity to AI drafts to editing to approval works, and so does publishing blogs to WordPress/Strapi. The big gaps are all after approval:

1. **Social posts are never actually published.** The Buffer publish action has no UI caller.
2. **"Scheduled" is only a label.** No job publishes anything when the scheduled time arrives.
3. **Failed publishes are recorded but never shown to anyone.**
4. **The approval workflow is enforced only in server actions.** Row Level Security (RLS) lets any workspace member set `status = 'approved'` directly, or edit the audit log.

The second-tier approval for high-sensitivity content can never trigger, because nothing in the app sets `sensitivity = 'high'`.

## Cross-cutting notes

- **Tests cover only pure functions.** [phase1.test.ts](../src/lib/content/phase1.test.ts) tests the transition table, the template generator and provider config. No tests cover `generateFromActivity`, `transitionAsset` role/tier gating, media analysis, Buffer publishing or the calendar generator, so every row above marked Partial is unprotected against regressions.
- **Hard-coded behaviour to replace:** template copy and hashtags ([template.ts](../src/lib/ai/template.ts)), RSS feed list ([trend-monitoring.ts:8-11](../src/jobs/trend-monitoring.ts#L8-L11)), calendar lead times and the `"linkedin"` fallback ([content.ts:491-499](../src/actions/content.ts#L491-L499)), the image platform fallback ([media.ts:51](../src/actions/media.ts#L51)), and the default Buffer `shareNow` mode.
- **Places where errors are swallowed:** fallback to the template generator ([provider.ts:276-281](../src/lib/ai/provider.ts#L276-L281)); `asset_approvals` inserts with unchecked results; the asset status update after a Buffer publish ([integrations.ts:82-86](../src/actions/integrations.ts#L82-L86)); brand-guidance lookups wrapped in `try {} catch {}` (acceptable, but never logged). There is no error tracking (INTEGRATIONS.md §4.6), so none of these show up in production.

## Suggested order

1. **A3 + A2**: make approval enforceable and the second tier reachable. This is the PRD's core governance promise, and today it can be bypassed.
2. **P1 → P2 → P3**: wire Buffer publishing into the UI, add a cron that publishes due assets, and show publication status and failures. Verify against a live Buffer account first.
3. **C5, C1, L4, A4**: small fixes that remove visible rough edges (timezone, calendar contents, manual create, character limits).
4. **P6**: complete the attribution path (mint on approval, redirect route, pass the token through).
5. **R3 → R6**: background transcription that handles real file sizes, then clip assets with adjustable boundaries.
6. **C2–C4, C6**: calendar views, drag-and-drop, AI timing, and a real AI calendar generator.
7. **L1–L3, R4, R5, R8, X1–X3**: remaining depth.
